# Ring List

Every weekday morning, a short list of who the agent should ring today from
their own CRM, why each one, a drafted opener under 40 words, and the things
to sort out on top. Built to AIP-BS-DATABASE-REACTIVATION 2026-10-24.

**Drafts only.** Ring List never dials and never sends. The agent makes every
call and every send, and marks each row done with what happened; tomorrow's
list is made from what was written back. The one call a machine may ring for
this standard (a contact who asked to be rung back) is Office Voice's governed
`create_call`, which is hosted and is not built here (check 14, `with_us`).

## Where each port goes on a real CRM

| port | wired to |
|---|---|
| `readContacts`, `missingFields` | the CRM export or the Contacts tab, read fresh each run |
| `rank` | the run record: every ranked contact with its play, trigger, score and plain-words reason |
| `gate` | the do-not-contact register kept where a re-import cannot reach it, calling hours in the contact's own state, and one opener a week |
| `listToday` | the Today tab, CRM tasks or a morning email to the agent (the `report_id`) |
| `recordOutcome` | the agent's done button, written to the CRM row the same day |
| `skip` | the audit log: one line per contact not on today's list, with its own reason |
| `escalate`, `noteReply` | the things-to-sort-out block on top of the list, naming the agent who owns it |

`disclose`, `say` and `sendStep` are never called.

## Who else can explain it (check 13)

Not a software check, so the run reports `evidence_required`. The operator
names a second person who can explain the plays, the weights in `WEIGHTS` and
the gate, and confirms the list and the CRM sit on an account the agency owns,
not the builder's.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

The call to a contact who asked to be rung back is Office Voice's governed single call: create_call, basis callback or they_asked. Everyone else on the list is the agent's own call from the daily list; Office Voice refuses prospecting calls by design. Queue each call with create_call on the Office Voice MCP (office_voice.create_call): the owner mints the key at office-voice.com/app/keys and ticks "Allow this to queue calls", and the dispatcher does the Do Not Call Register check, the calling hours and the one-attempt-a-day limit. There is no production run of these checks yet, so the stub run is the finished build. Do not stand up telephony of your own.

The checks that never go green on the stub report `with_us`.
