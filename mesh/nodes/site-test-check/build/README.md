# Site Test Check: fire-service-pack-standard harness

Site Test Check takes a finished fire service visit to a commercial site,
checks each test result against the site's asset register, holds any test
with no tagged asset or no tag photograph (and any asset due on the visit
with no test), and compiles the site's service report from the bound records
as a DRAFT for the person who attests. It never signs, certifies or decides a
pass. Before the committed run, the scenarios were run against a do-nothing
build and a naive build that stores every test as given: all eleven stub
checks went red for both.

Generated by `npx @aipathway/conformance init fire-service-pack-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

12 checks: 11 provable here on the stub, 1 only in
production, 0 partial, 0 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/fire-service-pack-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted product. The binding layer is quoted as a scoped build, run against the asset register and document store already in use. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.

## Handing this to a coding agent
