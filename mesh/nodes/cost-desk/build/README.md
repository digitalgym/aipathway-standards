# document-filing-build-standard: conformance harness

Generated by `npx @aipathway/conformance init document-filing-build-standard`,
then filled in for **Cost Desk**, an original Mesh Directory build: code each
supplier bill to the job it belongs to, by the purchase order number printed
on it, so the job's cost is current, and put every bill with no clear job on
one list for a person. Built from AIP-BS-DOCUMENT-FILING 2026-10-24 alone.

- `build.mjs` is the build. It files and types in; it never replies,
  approves or pays. A filed bill waits on its order for a person.
- `cost-world.mjs` is the stub world. The package ships none for this
  standard, so this one records every port call under the package's port
  names, and carries the shortcuts (search by address or supplier name, a
  writable file store, reply and pay ports) so a build that takes one shows.
- `scenarios.mjs` holds one `holds` per check, read off the trace.

The keying table (the business's, in `cost-world.mjs`): a supplier bill is
found by its purchase order number, and its bill number and total are typed
onto that order only when they read clearly and the lines add up. Every order
belongs to one job, so the bill is coded to that job. Dockets, quotes, job
sheets, certificates, statements and customer forms are filed by the job or
account number printed on them, so the daily close accounts for everything.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

14 checks: 12 provable here on the stub, 1 only in
production, 2 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/document-filing-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. Landing each document on its record by id in the business's own job system, entering only into blank fields and attaching the original unaltered, is quoted as a scoped build on the systems the office already runs. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.
