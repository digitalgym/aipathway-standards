# material-order-build-standard: conformance harness

Generated by `npx @aipathway/conformance init material-order-build-standard`.

This folder is **Van Stock**, an original build to AIP-BS-MATERIAL-ORDER
2026-10-03 for HVAC, refrigeration and other trade service businesses whose
techs carry stock on the van. Before anything is ordered for a job it reads
what the van and the store already hold and reserves it against the job; only
the shortfall becomes one purchase order per job and supplier, priced from the
supplier's own catalogue (AUD, ex GST). Orders under the release rule's
threshold to an approved wholesaler go out on the rule; everything else waits
for a named person. Every delivery docket is matched back line by line.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |
| `mutants.mjs` | ours | runs the scenarios against a do-nothing build and ten broken ones; every claimed check must go red |

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The idempotent write of the order into the system the business orders from is quoted as a scoped build. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.

## Proving the scenarios are not weak

    node mutants.mjs

The real build is `makeBuild()` with no breaks. Each mutant removes one thing
the standard requires (reading stock, the catalogue price, the dedupe key, the
release gate, the lead-time notice, the docket match, the variance queue, a
person on a substitution). Every check the run claims goes red for the
do-nothing build and for at least one mutant, or the script exits 1.

## It survives the builder (check 11)

Declared, not scored: the runner reports `evidence_required` and never turns it
green on its own say-so. The business's service manager and purchasing officer
can each explain it from this README and `build.mjs`: van stock first, the
shortfall to the approved wholesaler at catalogue price, the threshold rule
they set, and the docket matched back. It runs on the business's own job
system, its own supplier accounts and catalogues, and a release rule a named
person in the business sets and owns. Nothing runs on a personal account.
