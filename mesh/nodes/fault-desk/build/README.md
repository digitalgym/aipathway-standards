# Fault Desk: fault-triage-build-standard conformance harness

Fault Desk works the faults that come in before a tech is sent. Each call,
text, portal message or monitoring alarm is sorted against the business's own
written fault list (one sheet, versioned by edition). A safety signal (a gas
smell, sparking, smoke, water near electrics, a medical device without power,
or a fault the list marks safety) goes straight to the emergency path: the
emergency job is written first, then on-call is told once by its number, and
no step is given. A procedure the business marked safe for a customer, for
that customer's model, is read word for word on a call, or put word for word
in a text draft that a named person sends. Only the customer's yes to the
procedure's own question is logged as a remote fix. Everything else is one
job in ServiceM8 or Simpro carrying the fault matched, the steps tried and
what the customer said, or an update to the customer's open job. An alarm the
list does not mark as a job is parked on the exception queue. Every intake
leaves one log entry naming the list edition.

Narrowed from the job as found: the bot never texts a customer itself. Every
written reply is a draft a person releases. No video calls. Live calls are
answered by Office Voice Front Desk with the same fault list; the call branch
in `build.mjs` is what the stub drives to prove the order, and nothing here
dials or answers a phone. Prices always go to a person.

`fault-world.mjs` is the world the checks run in (the package's StubWorld is
a single after-hours call). It records every port call and decides nothing.

Generated by `npx @aipathway/conformance init fault-triage-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

10 checks: 9 provable here on the stub, 1 only in
production, 4 partial, 0 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/fault-triage-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

Point the number at Office Voice / Front Desk (Booked After Hours). There is no production run of these checks yet: AIPATHWAY_PROVIDER=office_voice.front_desk needs a live port map that is not published, so the stub run is the finished build. Do not stand up telephony of your own.

The checks that never go green on the stub report `with_us`.
