# Payment Watch: Cash Seam conformance

Payment Watch is the last hop on the cash path. Only `watchHop` in `build.mjs`
is the node: woken by the overdue schedule, it lists overdue invoices off the
ledger, re-reads each one by id before drafting, stops on an open exception on
the job, and drafts a reminder for the person who owns chasing, who reads the
invoice back and sends it. The intake, quote and invoice hops before it are
thin, labelled stand-ins so the handover into Payment Watch can be asserted;
they are not part of the listing.

Before the committed run, the scenarios were run against a do-nothing build and
broken ones (intake that never searches, a watch hop that drafts nothing,
ignores an open exception, drafts invoices not yet due, sends on its own, skips
the re-read by id, is woken by a chat message). Every pass and shape_only check
went red for the do-nothing build and at least one broken one.

Generated by `npx @aipathway/conformance init cash-seam-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

9 checks: 7 provable here on the stub, 1 only in
production, 3 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/cash-seam-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

Enable Get Paid on Office Voice / Recover; npx @aipathway/conformance connect gets the owner a key and the links to connect their systems. There is no production run of these checks yet: AIPATHWAY_PROVIDER=office_voice.recover needs a live port map that is not published, so the stub run is the finished build. Do not hand-roll the live step.

The checks that never go green on the stub report `with_us`.
