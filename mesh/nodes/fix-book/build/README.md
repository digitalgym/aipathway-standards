# Fix Book: knowledge-base-build-standard conformance harness

Fix Book keeps the fixes a service business's techs find on site. When a tech
sends the fix back, `fileNote()` turns the message into one fix note (fault,
cause, fix, parts, tested) for `Fixes/<job_id>/` on the shared drive, carrying
none of the customer's details (evidence.filed). Every fix note, voice memo,
service manual, procedure, template and rate sheet then goes on one register
with a named person as owner (a fix note's owner is the tech the job system
names on that job), a checksum and the edition the issuer printed. Only
registered, current, non-customer files are indexed, by section, page or
second.

When a tech asks how a fault was fixed before, `search()` returns the
passages that cover it, each with its register id, the job_id it came from and
a locator that opens the note at that section. It composes nothing. When
nothing covers the question the result is empty and the reply is the fixed
sentence "No record of this fix on our jobs." A scheduled watch re-fetches
every registered file, catches an amended fix note by its checksum and tells
its tech the same run.

Nothing here sends to a customer, and nothing is promoted to the graph without
a named person.

Generated by `npx @aipathway/conformance init knowledge-base-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

13 checks: 11 provable here on the stub, 1 only in
production, 0 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/knowledge-base-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The production check runs over the business's real drive and mailbox with its real owners. The watch is the part not to hand-roll: a scheduled re-fetch and checksum compare of every source, with the owner told when it moves. It is a schedule and a table, not a product. There is nothing to buy: your build does this step on the business's own systems. No production run is offered yet, because the live port map is not published, so do not run AIPATHWAY_ENV=production. Run the pass test by hand on the real systems and attach the evidence.

The checks that never go green on the stub report `with_us`.
