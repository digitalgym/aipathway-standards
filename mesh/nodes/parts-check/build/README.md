# parts-ready-build-standard: conformance harness

Generated by `npx @aipathway/conformance init parts-ready-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |
| `parts-world.mjs` | Parts Check | the stub world: tomorrow's board, jobs with quote lines and materials, needs templates, van counts with their as-of time, a shelf that refuses what it cannot cover, suppliers with lead times, a Material Order path that does not deduplicate, the seam mirror and the exception desk |
| `mutants.mjs` | Parts Check | runs the scenarios against a do-nothing build and 13 broken ones; every claimed check must go red |

    node mutants.mjs

## This standard

10 checks: 9 provable here on the stub, 1 only in
production, 2 partial, 0 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/parts-ready-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The check runs on the business's own board, van counts and shelf, and a shortfall is ordered through Material Order's path, whose order write is the builder's until Office Voice's purchase order tools ship. The pass test runs on the business's own systems. There is nothing to buy: your build does this step on the business's own systems. No production run is offered yet, because the live port map is not published, so do not run AIPATHWAY_ENV=production. Run the pass test by hand on the real systems and attach the evidence.

The checks that never go green on the stub report `with_us`.

## Handing this to a coding agent

`AGENTS.md` in this folder is written for one. Point your assistant at this
