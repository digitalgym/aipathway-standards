# next-service-build-standard: conformance harness

Generated by `npx @aipathway/conformance init next-service-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

15 checks: 13 provable here on the stub, 1 only in
production, 3 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/next-service-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. Writing each yes into the live job system as exactly one booking request against the right customer and asset, safe to retry, is the step not to hand-roll, and it is quoted as a scoped build on the job system the business already runs. Tradify has no public API, so it cannot meet that check live. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.

## Handing this to a coding agent

`AGENTS.md` in this folder is written for one. Point your assistant at this
directory and it has the standard, the harness and the rule it has to obey.

## Install Book

This folder is Install Book's build to AIP-BS-NEXT-SERVICE.

| file | what |
|---|---|
| `build.mjs` | the build: capture from the completed job, derive the dates, remind once, follow up once, one booking request per yes |
| `service-book-world.mjs` | the stub the standard names (`local.mock_service_book`), since the package ships none for this standard |
| `scenarios.mjs` | one `holds` per check, reading the trace only |
| `broken-builds.mjs` | runs every scenario against a do-nothing build and 24 broken builds; each scenario goes red for the do-nothing build and at least one broken one |

    npm install
    npm install --no-save ../../../../packages/conformance   # the fixed runner, 1.4.1
    node broken-builds.mjs
    node run.mjs

What it never does: hand the commissioning record to the customer, register
the warranty with the maker, book a time, price the work, or say what a
warranty covers. A person does each of those. The schedule months in the
fixtures are illustrative; the business writes its own from the maker's
instructions.
