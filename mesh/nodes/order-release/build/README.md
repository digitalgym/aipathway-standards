# Order Release: built to the Material Order standard

Order Release turns each job's material list into one purchase order per job
and supplier, and holds back any order over the spending limit, or to a
supplier nobody has approved, until a named person releases it.

Each run, in this order: read the jobs, read stock and reserve what it covers,
read the supplier list and each supplier's catalogue (the only source of a
price), read the release rule, then write one order per job and supplier (a
second run updates it by its id or leaves it alone). Under the limit and to an
approved supplier, the rule releases it by name and it is sent; otherwise a
named person is asked and nothing goes. A code no catalogue holds parks the
order unpriced. A supplier whose lead time misses the job's start tells the job
owner. Dockets are matched to their order by id, line by line; a docket with no
sent order, every short, over, wrong item, changed price and unaccepted
substitution goes to a named person with the order id.

What it never does: approve a supplier, accept a substitute, release over the
limit, or type a price. The live write into the supplier portal or the job
system's purchasing is a scoped build under the standard, not built here.

    npm install
    node run.mjs        # the evidence run, writes manifest.json and envelope.json
    node mutants.mjs    # the scenarios against a do-nothing, a naive and broken builds

## The scaffold

Generated by `npx @aipathway/conformance init material-order-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

12 checks: 10 provable here on the stub, 1 only in
production, 1 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/material-order-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The idempotent write of the order into the system the business orders from is quoted as a scoped build. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.
