# Cash Ahead: build and conformance harness

Cash Ahead publishes the 13-week cash forecast every Monday at 7:00 am AEST,
built to AIP-BS-RECURRING-REPORT 2026-10-03. It reads the operating bank
balance, open sales invoices and open bills from the ledger (Xero) and the pay
calendar and last finalised pay run from the payroll system (Xero Payroll).
Each forecast line (receipts, bill payments and payroll for each of the next
thirteen weeks) is one definition in the register, and each definition names
its assumption: when an invoice is assumed to be paid, when a bill is assumed
to be paid, what a pay run is assumed to cost. It cites the definition, source
and as-of time on every line, publishes one view per audience (owner, lender;
the lender never sees payroll), publishes a line it could not read as
unavailable and tells its owner, routes threshold crossings to the named
person, and takes corrections only as a new version by a named person.

It does not add the lines into a closing balance in its prose: a total is a
number the figure list does not carry. If the owner wants one, it goes in the
register as its own definition first. It pays nothing, runs no payroll and
sends nothing outside the business. A person decides what the forecast means
and who outside the business sees it.

    npm install
    node run.mjs        # the conformance run; writes manifest.json and envelope.json
    node mutants.mjs    # every scenario must go red for a do-nothing build and a broken one

The committed evidence is in ../evidence/recurring-report/.

## recurring-report-build-standard: conformance harness

Generated by `npx @aipathway/conformance init recurring-report-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

12 checks: 10 provable here on the stub, 1 only in
production, 1 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/recurring-report-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The production check runs over the business's own sources and definitions register, on its own schedule. There is nothing to buy: your build does this step on the business's own systems. No production run is offered yet, because the live port map is not published, so do not run AIPATHWAY_ENV=production. Run the pass test by hand on the real systems and attach the evidence.

The checks that never go green on the stub report `with_us`.
