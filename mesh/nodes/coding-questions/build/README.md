# Coding Questions: build and conformance harness

Coding Questions clears the bank lines a client's ledger cannot code from
history, built to AIP-BS-UNCODED-QUERY 2026-11-12. It is woken once a day by a
schedule. For each client file it reads the lines the ledger still shows as
uncoded, sends the client one plain-words list a month ("$412.50 to BUNNINGS
5678 MORAYFIELD on 3 Oct: what was it for?") with a link to answer each line,
reminds on the interval and count the practice set, and after the last
reminder hands the client's open lines to a person. Each answer is kept word
for word with who and when. A coding (account and tax code) is then proposed
from that client's own chart only, their own history for the payee first.
Nothing goes into the ledger until a named person approves it, and then only
exactly what they approved, under one key per line and approval, read back
after the write.

It never reconciles a bank line, never creates an account or borrows one from
another client, never tells a client what is deductible, and places no call.

## What each ledger allows (checked 2026-11-12)

| ledger | what it reads | how an approved coding is written |
|---|---|---|
| Xero | transactions parked on the suspense account. The API does not expose unreconciled bank feed lines | recode the transaction, or a manual journal off suspense, with an `Idempotency-Key` header |
| QuickBooks Online | purchases and deposits on Uncategorised Expense, Uncategorised Income or Ask My Accountant. For Review lines are not in the API | sparse update with a `requestid` |
| MYOB Business | the Banking Statement endpoint, which lists feed lines as Uncoded or Coded, and Spend or Receive Money on suspense | update Spend or Receive Money with its `RowVersion`. MYOB has no idempotency key, so the build reads the transaction back by id before any retry |

No ledger reconciles over its API. A line still in the bank feed gets its
question, its proposal and its approval, and then goes to a person with the
approved coding to reconcile (`reconcile_by_person`).

## Run it

    npm install
    node run.mjs        # the conformance run; writes manifest.json and envelope.json
    node mutants.mjs    # every scenario must go red for a do-nothing build and a broken one

The committed evidence is in ../evidence/uncoded-query/. On the stub: 10 pass,
3 shape_only (the ledger read, the approval gate and the read back, which only
a live ledger proves), 1 evidence_required (it survives the builder) and 1
with_us (the pass test on a real ledger, a scoped build).

## uncoded-query-build-standard: conformance harness

Generated by `npx @aipathway/conformance init uncoded-query-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

15 checks: 13 provable here on the stub, 1 only in
production, 3 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/uncoded-query-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted product writes a coding. The approval-gated, keyed write into the client's own ledger is built against that ledger's API, quoted as a scoped build. No follow-up call is offered: Office Voice has no lawful basis for one here, so the call stays with the person. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.

## Handing this to a coding agent

`AGENTS.md` in this folder is written for one. Point your assistant at this
directory and it has the standard, the harness and the rule it has to obey.
