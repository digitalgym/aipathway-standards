# Route Plan

Proposes the order of each tech's jobs for the day, and which licensed tech takes each recurring visit, so the vans drive less, to AIP-BS-DISPATCH-BOARD 2026-10-03. It tries each job at every position in every licensed tech's run, reads the travel for each leg, keeps every stop inside its window, and takes the position that adds the least travel; a recurring visit breaks a tie towards the tech who did it last. Lines already accepted are never reshuffled.

The dispatcher accepts the plan, line by line (`acceptPlan` in `build.mjs`). Only an accepted line becomes a slot on the job, and only then are the customer and the tech told. A declined line stays proposed for the next run. An emergency that fits nowhere proposes one displacement, which the named dispatcher accepts through the gate.

`build.mjs` is the planner, `scenarios.mjs` the world each check starts in, and `node mutants.mjs` shows every claimed check going red for a do-nothing build and for deliberately broken ones (including one that writes before the dispatcher accepts, and one that ignores route order). `node run.mjs` writes the manifest and envelope committed under `../evidence/dispatch-board/`.

The live slot write into ServiceM8, Simpro or Jobber and the live SMS are the scoped build the standard names, and are not written here. Maintained by AI Pathway in this public repository; it runs on the business's own job system account.

# dispatch-board-build-standard: conformance harness

Generated by `npx @aipathway/conformance init dispatch-board-build-standard`.

    npm install

Every check starts red. That is the point: going green is the work, and a green

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted dispatch step. Office Voice already writes the booked time into ServiceM8 and Simpro, one slot per job with the id back, but only inside a Front Desk call, day or night; a board cannot call it and it reads no licences. When a job slips on the ServiceM8 or Simpro board, its running-late call rings the customer, switched on under Automations. For a board, the write into the job system's schedule and the customer message with consent are quoted as a scoped build. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.
