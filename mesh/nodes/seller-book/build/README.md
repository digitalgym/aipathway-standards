# Seller Book

Each morning, the past sellers, owners and lapsed appraisals in an agency's
own database to text today, why each one, with the text drafted for the
agent's OK. It sends only what the agent OKs, stops a sequence the moment the
seller replies, and keeps every outcome and follow-up on the contact so
tomorrow's list is made from it. Built to AIP-BS-DATABASE-REACTIVATION
2026-10-24.

**Nothing goes without an OK, and nothing is priced.** Seller Book never states
a price, never makes or discusses an offer, and never dials. A reply that asks
what the place is worth, asks for an offer, or complains goes to a person with
a typed reason. A seller who asks to be rung goes to the top of tomorrow's list
for the agent; the optional governed callback is Office Voice's `create_call`,
hosted and not built here (check 14, `with_us`).

**Australian rules.** A text is a commercial electronic message under the Spam
Act 2003: it goes only to a contact with an existing relationship and no
`textConsent: false` on the record, names the sender, and ends "Reply STOP to
opt out". A STOP reply is a do-not-contact outcome across every play, held
where a re-import cannot clear it. Sending hours are the contact's local time,
enforced by the gate on the morning list and again when the OK arrives.

## Events

| event | what it does |
|---|---|
| `schedule.tick` (default) | the morning list: five fields, one play per contact, rank by `WEIGHTS`, gate under the rank, cap, publish |
| `text.approved` `{contactId, step, play}` | the agent's OK: re-read by id, re-gate, honour the cadence (three texts, a week apart), send, log it |
| `reply.received` `{contactId, text}` | stop the sequence; STOP opts out; a price, an offer or a complaint escalates |
| `outcome.marked` `{contactId, outcome}` | the agent's done button, written back the same day |

These are the build's own wake-ups. In the mesh it consumes `schedule.tick`
and `exception.closed`; the OK, the reply and the outcome arrive as changes on
the contact in the CRM.

## Where each port goes on a real CRM

| port | wired to |
|---|---|
| `readContacts`, `missingFields` | the CRM contacts or the Contacts tab, read fresh each run |
| `rank` | the run record: play, trigger, score and the reason in words |
| `gate` | the do-not-contact register and the contact's local sending hours |
| `listToday` | CRM tasks or the Today tab (the `report_id` of the day's list) |
| `sendStep` | the CRM's own SMS, only for a text the agent OK'd |
| `recordOutcome` | the contact row: the outcome and its date, the same day |
| `skip` | the audit log: one line per contact not texted, with its own reason |
| `escalate`, `noteReply` | the things to sort out, naming the agent who owns them |

## Proving the scenarios bite

`node negatives.mjs` runs every scenario against a do-nothing build and ten
deliberately broken ones (gate ignored, gaps hidden, cap ignored, generic
opener, reversed rank, history forgotten, one campaign for everyone, replies
or outcomes dropped, skips unexplained). Every claimed check goes red for the
do-nothing build and for at least one broken build.

## Who else can explain it (check 13)

Not a software check, so the run reports `evidence_required`. The operator
names a second person who can explain the plays, the weights and the gate, and
confirms the CRM and the list sit on an account the agency owns.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

The call to a contact who asked to be rung back is Office Voice's governed single call: create_call, basis callback or they_asked. Everyone else on the list is the agent's own call from the daily list; Office Voice refuses prospecting calls by design. Queue each call with create_call on the Office Voice MCP (office_voice.create_call): the owner mints the key at office-voice.com/app/keys and ticks "Allow this to queue calls", and the dispatcher does the Do Not Call Register check, the calling hours and the one-attempt-a-day limit. There is no production run of these checks yet, so the stub run is the finished build. Do not stand up telephony of your own.

The checks that never go green on the stub report `with_us`.
