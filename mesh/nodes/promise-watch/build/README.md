# debtor-chasing-build-standard: conformance harness

Generated by `npx @aipathway/conformance init debtor-chasing-build-standard`.

## Promise Watch, in this harness

- Woken by `schedule.tick` (the daily run), `email.received` (a client reply,
  filed by the invoice number it carries and read by id off the ledger, never
  by sender) and `exception.closed` (a named person lifting a hold).
- The world's `disclose` port is the moment of contact. For Promise Watch that
  is a chase draft entering the owner's approval queue, opening with a line
  saying an AI assistant drafted it. Nothing is sent without that approval,
  and nothing is dialled: live calls, the Do Not Call Register wash and the
  hosted gate stay `with_us`.
- `CONFIG` in `build.mjs` names the exception owner, the office timezone and
  the relationship-sized threshold.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

12 checks: 10 provable here on the stub, 1 only in
production, 1 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/debtor-chasing-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

Enable Get Paid on Office Voice / Recover; npx @aipathway/conformance connect gets the owner a key and the links to connect their systems. There is no production run of these checks yet: AIPATHWAY_PROVIDER=office_voice.recover needs a live port map that is not published, so the stub run is the finished build. Do not hand-roll the live step.

The checks that never go green on the stub report `with_us`.
