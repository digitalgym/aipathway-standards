# Review Ask

After each finished job, Review Ask prepares the business's one review
message for the customer (the same words and the same Google review link for
everyone), one reminder if nothing comes back, and then stops. A job with an
open callback, a disputed invoice or an open complaint is held, with the
reason, for the owner, and asked the same way once it clears. A reply of 1 to
3 texts the owner to call; the customer keeps the same link. A STOP is for good.

**A person releases every message.** Review Ask never sends on its own. Each
run it prepares what is due and hands the batch to a named person, who
releases it whole or not at all. They cannot edit a message or pick customers
out, so a release can never become a score filter. An unreleased batch is
prepared again on the next run.

It never writes, suggests, rewards, posts or answers a review. A message
the office writes that offers anything, or names stars, is refused and raised
to the owner.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted product. Reading the job's status, linked callbacks and invoice state from ServiceM8, Simpro, Fergus, Jobber or AroFlo at the moment of sending, and bringing SMS replies and STOPs back from the carrier, run on the business's own job system and messaging account and are quoted as a scoped build. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.
