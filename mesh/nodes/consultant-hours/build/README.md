# Consultant Hours: timesheet-check-build-standard conformance harness

Consultant Hours checks the hours consultants write on PDF timesheets before
the payroll run, to AIP-BS-TIMESHEET-CHECK 2026-10-03. Each PDF row becomes an
entry keyed `<document_id>#<row>`, flagged onsite or remote where the sheet
says so. `build.mjs` traces every entry to a person, a day and an allocated
job, raises anomalies from the closed list with an owner, cites the dated award
edition, carries a person's decision onto each anomaly, exports once to payroll
only after a named release, and publishes the period report every run with
onsite, remote and unknown hours per consultant. A row the sheet does not
place stays unknown; it is never guessed.

Generated by `npx @aipathway/conformance init timesheet-check-build-standard`.

    npm install
    node run.mjs          the conformance run; writes manifest.json and envelope.json
    node adversarial.mjs  runs the same scenarios against a do-nothing build and
                          twelve broken builds; every claimed check goes red

The award editions in `scenarios.mjs` are illustrative dated fixtures, not
quoted clause text. On the business's own systems, load the instrument it
actually uses and check it against the Fair Work Commission's published award.

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

13 checks: 11 provable here on the stub, 1 only in
production, 1 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/timesheet-check-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The production check runs over the business's own roster, entries and payroll system, released by a person. There is nothing to buy: your build does this step on the business's own systems. No production run is offered yet, because the live port map is not published, so do not run AIPATHWAY_ENV=production. Run the pass test by hand on the real systems and attach the evidence.

The checks that never go green on the stub report `with_us`.
