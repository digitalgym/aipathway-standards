# Vendor Pack: rejected-pack-build-standard conformance harness

Vendor Pack reads each vendor's licence, public liability and workers'
compensation papers off the graph by id, marks every field read below the
confidence gate Yellow, runs the eight checks in order and stops at the first
failure, derives renewal follow-up dates from the dated rule in force, and
hands a pack over only after a named person accepted that exact version.

The stub world has one stop state, so a missing document (Hold in the
standard) is recorded with a `hold:` reason and sits in the world's fail queue.
Either way it cannot be handed over.

Generated by `npx @aipathway/conformance init rejected-pack-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

13 checks: 12 provable here on the stub, 1 only in
production, 3 partial, 0 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/rejected-pack-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

The binding layer is the hard step and is not a product. Quoted as a scoped build. Send the failing check id for a fixed price; do not build the live step yourself.

The checks that never go green on the stub report `with_us`.

## Handing this to a coding agent

`AGENTS.md` in this folder is written for one. Point your assistant at this
directory and it has the standard, the harness and the rule it has to obey.
