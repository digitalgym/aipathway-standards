# Accrual Desk

Each month at month end, Accrual Desk drafts the accrual journals the month
needs in a client's Xero, MYOB or QuickBooks file. Costs that came in with no
bill yet come from the list the person keeps and from recurring bills that did
not arrive this month (a supplier billed in each of the three months before,
accrued at last month's amount before GST). Revenue earned but not invoiced
comes from completed work not yet billed. Each accrual is dated the last day of
the month and gets its reversal dated the first of the next.

Every journal then goes through the preview. The ledger's tax rates are read
first; each line is worked out again from its quantity, unit price and
discount; each line must name the ledger's own no-tax type, held at zero, since
an accrual carries no GST (the GST comes on the bill or invoice when it is
raised, and anything else goes to a person or the accountant). A journal a
cent away from its source total, naming a tax type the ledger does not hold,
or whose debits and credits differ is parked for the bookkeeper with both sets
of figures, and its reversal with it.

Nothing is written until a named person releases the preview. Then the journal
is written once, with the key `preview:<tenant>:<draft>:<preview>`, and read
back so the totals the ledger stored can be compared to the cent. A reversal
is written only after its accrual has read back equal. A dry run previews and
parks as usual and writes nothing. It never pays, approves or lodges anything.

Draft Preview checks drafts another bot hands it. Accrual Desk makes the
drafts: it is the bot that works out which accruals the month needs, then holds
each one to the same preview.

Built to AIP-BS-LEDGER-WRITE-PREVIEW. In production the preview comes from
preview_draft on the AI Pathway connector (connect.aipathway.com.au).

    node run.mjs              the conformance run
    node mutants.mjs          proof every scenario goes red for a do-nothing build and a broken one
    node --test draft.test.mjs  the drafting step, which the conformance run does not see

# ledger-write-preview-build-standard: conformance harness

Generated by `npx @aipathway/conformance init ledger-write-preview-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

13 checks: 11 provable here on the stub, 1 only in
production, 3 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/ledger-write-preview-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

AI Pathway's preview_draft, on the AI Pathway connector at connect.aipathway.com.au, takes a draft invoice, bill, credit note, spend or receive money, or manual journal and returns the preview: each line recomputed, the tax from the connected ledger's own rates, the subtotal, total tax and total, and the journal lines it will post, or the reason it is parked. Call it on the AI Pathway MCP (office_voice.preview_draft): the owner mints a key at connect.aipathway.com.au/app/keys with the scope the tool names, on any AI Pathway account. There is no production run of these checks yet, so the stub run is the finished build; AIPATHWAY_PROVIDER=office_voice.preview_draft needs a live port map that is not published. Do not hand-roll the write.

The checks that never go green on the stub report `with_us`.
