# Draw Match: conformance harness for two-records-build-standard

Draw Match keeps a small landlord's books in agreement with their managing
agent's owner statements, to AIP-BS-TWO-RECORDS. Source a is the owner's books:
each deposit from the agency as it landed on the bank feed (Xero or similar),
coded into rent, fees and net. Source b is the agency's owner statement
register: each disbursement line from the agency's trust account statement
(PropertyMe, Console Cloud and the like), filed as received. They join on the
payment_id the agency's trust ledger issues for each disbursement and prints in
the EFT reference, never on the address, the tenant or the amount.

The written contract says the bank is master for the net that landed and the
agency statement is master for rent collected and fees charged. A pair that
agrees is counted; a field that differs is a Difference with both values and
the master's value; a deposit with no statement line, or a statement line with
no deposit, is an orphan for the owner's bookkeeper; a correction is written
only after a named person accepts it, with both originals kept; every run
publishes its counts, the all-clear included. A short-pay over the threshold
reaches the named person that run. Nothing is corrected automatically.

Not in scope: mortgage, council rates, land tax and insurance. Those are other
pairs with other keys, and each needs its own written contract.

The ports carry the pair as the standard's stub names them: `read_job` reads
source a (the owner's books), `read_ledger` reads source b (the agency
statements) and the contract.

Generated by `npx @aipathway/conformance init two-records-build-standard`.

    npm install
    node run.mjs

Every check starts red. That is the point: going green is the work, and a green
run means something because a red one was possible.

## The three files

| file | whose | what |
|---|---|---|
| `build.mjs` | yours | the build. The only file that does the job |
| `scenarios.mjs` | yours | one `holds` per check. Generated with the check's own words |
| `run.mjs` | ours | fetches the checks, runs, prints. No edits needed |

## This standard

12 checks: 10 provable here on the stub, 1 only in
production, 1 partial, 1 preconditions needing evidence rather than code.

The checks are fetched at run time from https://aipathway.com.au/explore-ai/two-records-build-standard,
so a correction published there reaches you without a release here.

## The second run

There is no second run for this standard yet. Its live port map is not
published, so this folder has no `ports.mjs`, and `AIPATHWAY_ENV=production`
is refused rather than rerunning the stub under a production label. The stub run
is the whole of what can be proved here.

This standard has no hosted provider, so `conformance connect` does not apply to it.

No hosted step. The production check runs over the business's own two sources with a person on every correction. There is nothing to buy: your build does this step on the business's own systems. No production run is offered yet, because the live port map is not published, so do not run AIPATHWAY_ENV=production. Run the pass test by hand on the real systems and attach the evidence.

The checks that never go green on the stub report `with_us`.
